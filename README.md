# UAV_System — симуляция + учёт БПЛА в одной программе

Запуск: `python main.py` из этой папки или двойной щелчок по `run.bat`.
Перед первым запуском: `pip install -r requirements.txt`

Открываются два окна: карта Ижевска и менеджер учёта. Если менеджер закрыть,
его можно снова открыть кнопкой «СИСТЕМА УЧЁТА».

## Как связаны части
- Летают те БПЛА, что записаны в реестре менеджера (таблица `drones` в `data/uav.db`).
- Зарегистрировали БПЛА — он сразу вылетает. Списали — исчезает с карты.
  Отремонтировали — получает новый номерной ID и новую сессию.
- Красные и жёлтые объекты от кнопок и «П-ТРАНЗИТ» не зарегистрированы, сессионного ID у них нет.

## Двойная защита ID
1. **Номерной ID** (постоянный) + подпись HMAC в ответе дрона.
2. **Сессионный ID** (`S-XXXXXXXXXXXX`) — новый на каждый полёт. Таблица связей:
   таблица `sessions` в `data/uav.db` (сессионный ID ↔ заводской номер ↔ номерной ID ↔ маршрут ↔ время ↔ статус).
   Станция принимает ответ, только если SID активен и принадлежит этому дрону.
   Закрытый SID (полёт завершён, прерван, БПЛА списан) больше никогда не принимается.

Историю полётов можно посмотреть на вкладке «Полёты» в менеджере, там же есть поиск.

## Структура
- `config.py` — общие настройки и пути
- `core/` — база данных, реестр, валидация, сессии (без интерфейса)
  - `database.py` — подключение к SQLite, схема таблиц, перенос старых CSV
- `simulator/` — карта и симуляция
- `manager/` — менеджер учёта:
  - `window.py` — главное окно, собирает вкладки вместе
  - `service.py` — правила учёта: регистрация, ремонт, списание (без интерфейса)
  - `widgets.py` — общие помощники интерфейса
  - `repair_window.py` — окно ремонта одного БПЛА
  - `tabs/` — по файлу на вкладку: регистрация, ремонт, каталог, полёты, списание, справка
- `data/` — база `uav.db` и выгрузка `objects.xlsx`

## База данных (SQLite)
Все данные учёта лежат в одном файле `data/uav.db`: таблицы `drones` (реестр),
`deleted_drones` (архив списанных) и `sessions` (полёты).
- Дубликат заводского номера или номерного ID база не пропустит (`PRIMARY KEY` / `UNIQUE`).
- Списание (удаление из реестра + запись в архив) идёт одной транзакцией.
- Все запросы параметризованы (`?`), поэтому SQL-инъекция через поля ввода невозможна.
- При первом запуске данные из старых CSV (`drone_components.csv`, `deleted_drones.csv`,
  `sessions.csv`) переносятся в базу автоматически. После этого CSV программой не используются.
- Посмотреть базу можно программой DB Browser for SQLite.

Ключ HMAC в коде не хранится: он берётся из переменной окружения `UAV_SIM_KEY`,
а если её нет — из файла `data/.sim_key`, который создаётся случайным при первом запуске.
Этот файл никому не передавайте и не выкладывайте (он в `.gitignore`).

## Карта
Карта-подложка берётся с открытых серверов (Esri, OpenStreetMap, OpenTopoMap — список в `config.TILE_SERVERS`).
Сервер, который вместо карты отдаёт заглушку «API KEY REQUIRED», программа распознаёт и пропускает.
При запуске программа сама выбирает первый живой сервер. Подпись источника — в правом нижнем углу карты.

**Офлайн-карта Ижевска.** Один раз, при наличии интернета, выполните:

    python download_map.py              # до зума 15, ~2200 тайлов
    python download_map.py --max-zoom 16   # подробнее, ещё ~80 МБ

Карта сохранится в `data/map_tiles.db`. После этого программа берёт тайлы сначала из неё,
а без интернета — только из неё. Скачивание можно прервать и продолжить.
